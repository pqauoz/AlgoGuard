ALGOGUARD USER MANUAL
Version: Seven-Model Training and Deployment Workflow

======================================================================
1. WHAT ALGOGUARD IS
======================================================================

AlgoGuard is a local Flask web application for binary network traffic
classification. It accepts one labeled CSV dataset at a time, trains seven
machine-learning approaches, compares them using nine metrics, recommends the
best valid model, and lets an administrator deploy the recommendation.

After deployment, an admin can enter one traffic record manually. AlgoGuard
classifies it as Normal or Attack using only the active deployed pipeline.

AlgoGuard does not capture live packets, monitor a network continuously, or
block an attack. It is a research and capstone prototype for prepared CSV data
and manual prediction.


======================================================================
2. FRONTEND AND BACKEND
======================================================================

The project contains both.

Frontend:
- HTML templates in templates/
- Bootstrap 5 components
- Dark dashboard styles in static/css/style.css
- Forms, tables, status badges, filters, and navigation

Backend:
- Flask routes in app.py
- Pandas and Scikit-learn services in services/
- SQLite records in database/algoguard.sqlite3
- Joblib artifacts in saved_models/
- CSV reports in reports/

The browser sends forms or JSON to Flask. Flask validates the request, calls
the relevant service, saves records, and renders the response page.

======================================================================
4. FIRST-TIME INSTALLATION
======================================================================

Open PowerShell in the project root. The correct directory contains app.py,
requirements.txt, services/, templates/, and static/.

Example:

  cd C:\Users\Client\Documents\AlgoGuard

Create a virtual environment:

  py -m venv venv

Activate it in PowerShell:

  .\venv\Scripts\Activate.ps1

Install the application dependencies:

  python -m pip install --upgrade pip
  python -m pip install -r requirements.txt

If activation is blocked or confusing, use the virtual-environment Python
directly:

  .\venv\Scripts\python.exe -m pip install -r requirements.txt
  .\venv\Scripts\python.exe app.py

The command prompt normally begins with (venv) after activation. Installing
packages with one Python and running a different Python causes errors such as:

  ModuleNotFoundError: No module named 'flask'


======================================================================
5. DATABASE MIGRATION
======================================================================

Run this from the project root after pulling a version with schema updates:

  python migrate.py

The migration is additive. It creates missing tables and columns without
deleting existing admins, model records, predictions, alerts, reports, or logs.
The app also checks migrations at startup.

Do not delete database/algoguard.sqlite3 as an upgrade method. Deletion removes
local records. Back up the file before important demonstrations.


======================================================================
6. STARTING ALGOGUARD
======================================================================

From the project root with the environment active:

  python app.py

Open:

  http://127.0.0.1:5000

The default account is created only when a new database has no admins:

  Username: admin
  Password: admin123

Set stronger credentials and a secret before the first run of a new setup:

  $env:ALGOGUARD_ADMIN_USERNAME = "your_admin"
  $env:ALGOGUARD_ADMIN_PASSWORD = "your-strong-password"
  $env:ALGOGUARD_ADMIN_EMAIL = "admin@example.com"
  $env:ALGOGUARD_SECRET_KEY = "a-long-random-secret"
  python app.py


======================================================================
7. LOGIN, SESSIONS, AND MULTIPLE ADMINS
======================================================================

AlgoGuard uses Flask session-based login. The browser stores a signed session
cookie after a successful login. The password is not placed in that cookie.

A login session is not the same as a permanent API token. It ends when the
admin logs out, the cookie is removed, or the application invalidates it.
Admin accounts themselves are permanent SQLite records until they are changed
or removed through database administration.

Passwords are stored as password hashes, not readable plain-text passwords.

An Administrator can open Admins and create multiple accounts. Supported roles:
- Administrator: can use the system and create admin accounts
- Analyst: can use operational pages but cannot create admin accounts

9. HOW TO CREATE A CSV FILE
======================================================================

Method A - Microsoft Excel:

1. Open a blank workbook.
2. Type column names in the first row.
3. Add one network traffic observation per following row.
4. Put the target label in the last column.
5. Select File, Save As.
6. Choose CSV UTF-8 (Comma delimited) (*.csv).
7. Save the file.

Method B - Notepad:

1. Enter column names separated by commas.
2. Put each traffic record on a new line.
3. Keep the same number and order of values on every row.
4. Save the filename with a .csv extension and UTF-8 encoding.

Example:

  dur,proto,service,state,spkts,dpkts,sbytes,dbytes,rate,sttl,dttl,sload,dload,sinpkt,dinpkt,label
  2.001348,tcp,-,FIN,16,14,862,802,14.490233,254,252,3233.820312,2977.99292,133.423196,146.368077,Normal
  1.665064,tcp,ftp-data,FIN,14,6,8928,320,11.410973,31,29,39835.10547,1282.833618,128.081847,332.462,Normal
  0.472012,tcp,http,FIN,10,8,834,354,36.016032,254,252,12728.48926,5254.103516,52.445778,60.35343,Attack
  0.320972,tcp,http,FIN,10,8,784,1256,52.964122,62,252,17596.55078,27391.79688,35.663556,38.518145,Attack

Do not add commas inside ordinary text values unless the value is correctly
quoted according to CSV rules.


======================================================================
10. WHAT ROWS AND COLUMNS MEAN
======================================================================

A row represents one observation. In network data, it may represent one flow,
connection, summarized packet group, or event depending on the source dataset.

A feature column represents one property measured for every observation. The
three included AlgoGuard datasets use these 15 input features:

dur:
Total duration of the traffic flow.

proto:
Network protocol, such as tcp, udp, or icmp.

service:
Detected network service, such as http, dns, ftp-data, or ssh. A dash means no
specific service was identified in the source data.

state:
Connection state, such as FIN, CON, REQ, or INT.

spkts and dpkts:
Packet counts from source to destination and destination to source.

sbytes and dbytes:
Byte counts from source to destination and destination to source.

rate:
Overall packet rate for the traffic flow.

sttl and dttl:
Source and destination time-to-live values.

sload and dload:
Source and destination traffic load rates.

sinpkt and dinpkt:
Source and destination packet inter-arrival times.

label:
The known answer used for supervised learning. It must be the last column.

This is the standardized schema for the included files, but it is not a fixed
requirement for every external CSV. AlgoGuard learns the feature list from each
uploaded CSV and saves it with the deployed artifact. Prediction input must
match the schema used to train that deployed model.


======================================================================
11. WHAT TO PUT IN THE TARGET COLUMN
======================================================================

The final column must contain exactly two classes representing:

- Normal: expected or benign traffic
- Attack: anomalous or malicious traffic

Recommended labels are Normal and Attack. AlgoGuard also recognizes common
normal labels such as 0, benign, legitimate, and clean. With another binary
pair, it selects a consistent mapping, but explicit Normal and Attack labels
make the dataset and documentation easier to understand.

Both classes need at least three rows for validation. A useful model needs many
more representative examples. The three-row rule only prevents an impossible
stratified split; it does not guarantee reliable model quality.

What happens if an Attack row is added?

The row becomes one labeled training example. It does not add an alert and does
not force all similar future traffic to be classified as Attack. The seven
models learn statistical boundaries from all training rows. The held-out test
rows evaluate how well those learned boundaries generalize.

Do not invent attack labels merely to improve a metric. Incorrect labels teach
the wrong behavior and make Accuracy, Recall, F1, and ROC-AUC misleading.


======================================================================
12. CSV VALIDATION RULES
======================================================================

The upload must:
- Be one .csv file
- Have a header row
- Contain at least one usable feature column
- Use the last column as the target
- Contain exactly two non-missing target classes
- Have enough rows in both classes for stratified training and testing
- Avoid duplicate column names

Feature columns can be numeric or categorical. Completely empty feature columns
are removed. Numeric and categorical missing values are imputed by the saved
pipeline. Unseen text categories during prediction are ignored safely by the
one-hot encoder.


======================================================================
13. ONE CSV PER TRAINING RUN
======================================================================

Every upload creates a new run ID. AlgoGuard never merges the new CSV with an
older upload and never overwrites an older run.

Each run stores:
- Admin ID
- Original and stored filenames
- Upload timestamp
- Row and feature counts
- Target column and class distribution
- Validation, preprocessing, and training status
- Seven model result records
- Recommended model and normalized score
- Deployment status
- Completion time or safe error message

Use Runs to compare separate Big, Bigger, and Biggest experiments manually.
AlgoGuard does not calculate a cross-dataset winner automatically.


======================================================================
14. PREPROCESSING AND DATA LEAKAGE PREVENTION
======================================================================

AlgoGuard performs a stratified train/test split before fitting preprocessing.
The test set is not used to calculate imputations, scaling values, or encoded
categories.

For each model pipeline:
- Missing numeric values use the training median
- Numeric values use StandardScaler
- Missing categorical values use the training mode
- Categorical values use OneHotEncoder
- Unknown prediction categories are ignored safely

Every model uses the same raw training and test records. Each complete Joblib
artifact contains preprocessing and its classifier together. This prevents the
manual prediction page from using mismatched columns, scaling, or encoding.


======================================================================
15. THE SEVEN MODEL APPROACHES
======================================================================

1. Random Forest
Builds many decision trees from sampled training data and combines their votes.
It captures nonlinear patterns and interactions and is generally robust.

2. Gradient Boosting
Builds trees sequentially. Each stage focuses on errors from the preceding
stages, producing a strong combined classifier.

3. AdaBoost
Sequentially increases attention on misclassified examples and combines weak
learners into a weighted classifier.

4. K-Nearest Neighbors
Classifies an input using nearby training observations. Scaling is important,
which is why KNN is inside the same preprocessing pipeline.

5. Naive Bayes
GaussianNB estimates class probabilities under a conditional independence
assumption. It is efficient and provides a useful probabilistic baseline.

6. Soft Voting Ensemble
Uses fresh instances of all five individual estimators. It averages predicted
class probabilities. It is soft voting, not hard voting.

7. Stacking Ensemble
Uses fresh instances of all five individual estimators as base learners.
Logistic Regression learns from their probability outputs as the final
estimator. Gradient Boosting is a base learner, not the stacking meta-learner.


======================================================================
16. THE NINE RANKING METRICS
======================================================================

Higher is better:

Accuracy:
The percentage of all test rows classified correctly.

Precision:
Of rows predicted as Attack, the percentage that were actually Attack.

Recall:
Of actual Attack rows, the percentage detected as Attack.

F1-score:
The harmonic balance between Precision and Recall.

ROC-AUC:
How well attack probabilities rank Attack above Normal across thresholds.

Lower is better:

False Positive Rate:
FP / (FP + TN). It measures Normal rows incorrectly classified as Attack.

CPU Usage:
Process CPU time in seconds consumed during fitting and test prediction.
It is not a CPU percentage.

RAM Usage:
Peak increase in the Flask process resident memory during the same measured
interval, stored in MB.

Model Size:
Size in MB of the complete serialized Joblib artifact, including preprocessing
and classifier.

Processing or wall time may be stored for reference but is not a tenth ranking
metric. Prediction latency is stored only for individual prediction records.


======================================================================
17. NORMALIZATION, SCORE, AND RECOMMENDATION
======================================================================

Raw percentages, seconds, and MB cannot be averaged directly. AlgoGuard applies
min-max normalization across valid candidates for each metric.

Higher-is-better formula:

  (value - minimum) / (maximum - minimum)

Lower-is-better formula:

  (maximum - value) / (maximum - minimum)

After normalization, values closer to 1 are better. If every valid model has the
same value for one metric, each receives 1.0 because that metric cannot separate
the models.

The overall score is:

  sum of the nine normalized metric scores / 9

All nine metrics receive equal weight. A missing or invalid required metric is
not changed to zero. That candidate is marked incomplete and excluded from
automatic winner selection.

The highest valid score becomes the recommendation. A tie is resolved by higher
F1, higher Recall, higher ROC-AUC, lower FPR, lower RAM, lower model size, then
alphabetical model name. No model type is forced to win.


======================================================================
18. DEPLOYING A MODEL
======================================================================

Training does not automatically replace the active model.

1. Open Runs.
2. Open a completed run.
3. Review all raw and normalized values.
4. Select Deploy recommended model.
5. Confirm the action.

The active artifact stores:
- Fitted preprocessing pipeline
- Fitted classifier
- Model name and type
- Source run ID
- Feature schema and defaults
- Label mapping
- Metric summary
- Deployment timestamp

The deployed winner can be an individual model, Soft Voting, or Stacking. A new
deployment marks the previous deployment inactive while preserving its database
history. If artifact validation or the database update fails, deployment rolls
back safely where possible.


======================================================================
19. MANUAL PREDICTION
======================================================================

Open Predict after a model is deployed. The form fields are generated from the
active artifact, so different datasets can produce different forms.

For one prediction, AlgoGuard displays and saves:
- Normal or Attack
- Confidence percentage
- Active model name
- Prediction timestamp
- Prediction latency in milliseconds
- Whether an alert was created

Accuracy, Precision, Recall, F1, ROC-AUC, and FPR do not appear as metrics for a
single prediction. They require a labeled dataset, not one unknown record.

When prediction is Attack:
- The traffic input is saved
- The prediction is saved
- One alert is created
- Attack and alert events are written to System Logs

When prediction is Normal:
- The traffic input is saved
- The prediction is saved
- No attack alert is created
- A successful Normal event is written to System Logs


======================================================================
20. ALERT HISTORY VERSUS SYSTEM LOGS
======================================================================

Alert History contains anomalous predictions. It includes severity, status,
model, confidence, prediction ID, detection time, and description.

System Logs contain operational and audit events, including:
- Successful and failed login
- Logout
- Upload and validation
- Preprocessing
- Each model training start, completion, or failure
- Metric normalization and recommendation
- Deployment and replacement
- Prediction, Attack, Normal, and alert creation
- Reports and application failures

Logs can be filtered by date, module, status, model, run ID, and search text.
They are paginated and displayed newest first.


======================================================================
21. INCLUDED BIG, BIGGER, AND BIGGEST FILES
======================================================================

AlgoGuard includes three actual CSV files in the datasets folder:

- algoguard_big.csv: 5,000 rows
- algoguard_bigger.csv: 10,000 rows
- algoguard_biggest.csv: 20,000 rows

These files are nested, stratified, non-replacement samples of the labeled
UNSW-NB15 training partition. The 5,000-row file is contained in the 10,000-row
file, which is contained in the 20,000-row file. Each file contains 15 traffic
features plus the final label column. The features are dur, proto, service,
state, spkts, dpkts, sbytes, dbytes, rate, sttl, dttl, sload, dload, sinpkt, and
dinpkt. Other source columns, including the identifier and attack_cat, were
removed to simplify training and prevent identifier noise or direct target
leakage. The binary target uses Normal and Attack labels.

Class distributions:
- algoguard_big.csv: 1,597 Normal and 3,403 Attack
- algoguard_bigger.csv: 3,194 Normal and 6,806 Attack
- algoguard_biggest.csv: 6,388 Normal and 13,612 Attack

Source and attribution:
The UNSW-NB15 Dataset, UNSW Research
https://research.unsw.edu.au/projects/unsw-nb15-dataset

Academic work using these files should cite the dataset publications listed by
UNSW Research.

Upload the files one at a time through the Upload page. Wait for one run to
finish before selecting the next file. AlgoGuard creates three independent run
IDs and does not merge their rows or choose a cross-dataset winner.

25. COMMON ERRORS
======================================================================

ModuleNotFoundError: No module named 'flask' or 'pandas'

Cause: The application is using a Python where dependencies are not installed.

Fix:
  .\venv\Scripts\Activate.ps1
  python -m pip install -r requirements.txt
  python app.py

Or use:
  .\venv\Scripts\python.exe app.py


CSV rejected as one class

Cause: The last column contains only Normal or only Attack, or the target is not
the final column.

Fix: Verify the final column and include correctly labeled examples from both
classes.


Insufficient rows

Cause: A class cannot be preserved in both the training and testing subsets.

Fix: Add more unique, valid examples for the smaller class.


No active deployment

Cause: Training finished but no administrator deployed the recommendation.

Fix: Open the run result and deploy the recommended model.


Active artifact missing or mismatched

Cause: saved_models/deployed_model.joblib was moved, deleted, or does not match
the active database record.

Fix: Redeploy a valid recommendation from a completed run.


Port 5000 already in use

Fix in PowerShell:
  $env:ALGOGUARD_PORT = "5001"
  python app.py

Then open http://127.0.0.1:5001.


======================================================================
26. INTERPRETING RESULTS RESPONSIBLY
======================================================================

High Accuracy can hide missed attacks when Normal rows dominate. Review Recall,
F1, ROC-AUC, and FPR together. Resource values depend on the computer, Python
version, background activity, and dataset size. Compare models measured in the
same run and environment.

An anomaly prediction is a model estimate, not proof of an attack. A capstone
evaluation should document dataset source, labels, class balance, split method,
software versions, computer specifications, resource method, and test results.

AlgoGuard's results should support human analysis. They should not be treated as
an automatic production security decision without additional validation.
